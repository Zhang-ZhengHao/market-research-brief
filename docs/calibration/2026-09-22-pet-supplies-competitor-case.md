# 案例校准：宠物用品竞品周报

- 日期：2026-09-22
- 用途：用一组接近真实客户资料的合成内容，验证来源顺序、原文证据、AI 来源索引和失败回退。

## 主题与输入

- 主题：`宠物用品竞品周报`
- 报告角度：`研究简报`
- 来源模式：手工粘贴，5 份资料，均为合成资料；参考链接不触发外部访问。

| 顺序 | 标题 | 资料正文要点 |
|---:|---|---|
| 1 | 尾巴友好｜新品公告 | 2026-09-10 发布低敏冻干零食，首发价 39 元/袋，单一蛋白配方。 |
| 2 | 宠物电商周报｜促销观察 | 多家店把满 99 元包邮调整为满 79 元，并使用第二件八折。 |
| 3 | 平台公告｜运费险规则 | 2026-09 起部分易碎宠物用品的运费险展示方式调整，详情页需补退换货说明。 |
| 4 | 用户评测｜真实反馈 | 单个用户认为适口性不错，但包装密封性一般；结论不能代表全部用户。 |
| 5 | 尾巴友好｜售后 FAQ | 未开封食品支持七天无理由退货，质量问题需提供照片和批次信息。 |

## 验收断言

1. 规则模式生成 5 个来源，标题和顺序必须与输入一致。
2. 每个成功来源的 `evidence` 必须是对应正文的连续子串，不能来自模型编造文本。
3. 模拟 AI 故意以乱序、数字字符串 `source_index` 返回摘要；最终摘要必须重新对齐为 S0、S1、S2、S3、S4。
4. 将第 5 个来源改为失败来源后，即使模型返回伪造摘要，结果中的摘要和证据也必须为空，并保留原始错误。
5. AI 提示词不得包含失败来源正文。
6. Markdown/JSON 导出必须保留 5 个来源及其顺序。

另外增加一个更危险的变体：把第 3 个来源改成失败来源（零基索引 2），让模型只返回成功来源 0、1、3、4，并故意打乱返回顺序。这样可以检验失败来源不会让后续来源发生“索引压缩”错绑。

## 结论与边界

本案例证明的是“数据不串、证据可回看、失败来源不被模型补写、导出不丢来源”。它不证明模型摘要的事实准确率，也不等于真实供应商线上验收；真实 AI 仍需人工核对原文。

## 中间失败来源变体结果

```json
{
  "source_order": ["A｜官方公告", "B｜行业媒体", "C｜用户社区", "D｜开发者文档", "E｜价格页"],
  "summaries_after_alignment": ["A 摘要", "B 摘要", "", "D 摘要", "E 摘要"],
  "failed_middle_source": {"summary": "", "evidence": "", "error": "资料不可用"},
  "prompt_indexes": [0, 1, 3, 4],
  "failed_text_excluded": true,
  "fallback_mode": "演示规则（AI失败回退）",
  "status": "PASS"
}
```

这个变体是本次校准的关键闸门：成功来源仍按 A、B、D、E 对齐，C 不会吞掉 D 或 E 的摘要。

## 负向校准与修复

另外用重复索引（两个 `source_index=0`）和越界索引（`source_index=9`）做了负向实验。修复后，重复索引不会再直接采用第一项，目标来源会回退到本地证据；缺失、重复、越界都会在报告 warning 中明确提示。这样模型格式异常不会再静默通过。

## 页面级自检

用 Streamlit `AppTest` 按页面真实控件填写 5 份资料并提交，结果为：

```json

  "success_message": "已载入 5 份手工粘贴资料；应用不会访问其中的参考链接。",

}
```

五个唯一标记（`ALPHA_ONLY`、`BRAVO_ONLY`、`CHARLIE_ONLY`、`DELTA_ONLY`、`ECHO_ONLY`）均在报告来源明细中保留。
